Descriptor details

Quick reference

0 · stdin Standard input1 · stdout Standard output2 · stderr Standard error
cmd | next
Connect stdout to the next command’s stdin.
< file
Read stdin from a file.
> file / >> file
Write stdout to a file / append to a file.
2> errors.log
Write stderr to a separate file.
2>&1
Copy stdout’s current destination to stderr.
&> file / &>> file
Write / append both output streams to a file.
cmd |& next
Pipe both output streams, applying the stderr copy after explicit redirects.
2>&-
Close a descriptor.
2> >(cmd)
Send stderr to another command’s stdin. The command inherits the current descriptors, and Bash does not wait for it.
cmd <(other)
Pass /dev/fd/63 as an argument; reading it reads other’s stdout.

Connections and usage

A solid line shows a connection, not observed data flow. A grey dashed line means a connected descriptor is not used by the command. Hollow ports are unused; dotted ports have unknown usage. Closed descriptors are labelled separately.

“May read”, “may write”, and “on error” describe possible use, not guaranteed traffic. “No writes” is a static prediction, not a measured byte count. Commands in a pipeline run concurrently; the foreground shell waits for all of them to finish.

Usage hints cover wc, base64, /usr/bin/time, true, false, sleep, echo, printf, cat, xargs, ls, cut, paste, awk, sed, rev, head, and tail. Common options and file arguments are recognised. Advanced scripts and unseen script files can leave individual streams unknown. They assume no aliases or replacement functions. Other commands and unrecognised argument forms remain conservative.

This is a static map of a simple Bash-style pipeline. It does not run commands, inspect files, or expand variables. Shell scripts, command substitutions, and here-documents are outside its scope.
